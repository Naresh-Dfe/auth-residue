# Coverage and limitations

- Only Chromium is supported. Windows is the locally exercised platform; CI defines Linux/macOS coverage, which must pass remotely before those compatibility claims are made.
- Browser HTTP/2 and QUIC are disabled for origin enforcement through a temporary loopback proxy. HTTP/1.1 and TLS/WebSocket tunnels are supported; protocol-specific production behavior, WebTransport, WebRTC, and arbitrary non-HTTP transports are outside coverage. The proxy streams data only in memory and is closed with the browser; no external-facing server is started.
- Scenarios are sequential. Accounts and server-side state remain application resources; independent browser contexts cannot reset a developer's database or shared account state. Use dedicated synthetic fixtures.
- Private assertions use exact configured identity text and substring matching of distinct synthetic canaries in visible private selectors or bounded GET response text. They do not inspect arbitrary personal data, structured JSON authorization policies, images, canvas, or full shadow-DOM trees.
- By default UI absence is observed after DOMContentLoaded. Use route readySelector for hydrated/delayed views. No finite observation can exclude future data exposure. Back/forward coverage depends on Chromium history behavior; a traversal without a document response is NOT_TESTED.
- API probes are GET only, cookie-authenticated, bounded, non-redirecting, and do not save Set-Cookie responses. They request identity encoding; unsupported encoded bodies are INCONCLUSIVE. Bearer extraction/replay, credential rotation, permission changes, refresh-token flows, MFA, hardware-bound credentials, OAuth-provider automation, and destructive requests are not implemented.
- Session replay tests server access with former cookies, not successful browser storage restoration or all client credential mechanisms. Cookie attributes are observed only as aggregates; no blanket cookie-policy security audit is claimed.
- localStorage/sessionStorage inspect the current origin/tab. Cookies are current-URL scoped. IndexedDB/CacheStorage are opt-in with entry/body-processing bounds. Browser enumeration APIs can return metadata before processing bounds apply. Inaccessible, opaque, oversized, or blocked stores cannot produce a clean PASS. Keys, database names, values, and cache bodies are never reported.
- Storage retention is not by itself cross-account exposure. Configure retention forbid only when removal of the tested canary is an explicit requirement. A storage category without an authenticated marker baseline is NOT_TESTED.
- Service workers are blocked to preserve page-request interception. Their persistence, cache logic, network ownership, and actual production behavior are NOT_TESTED. See [Playwright's service-worker documentation](https://playwright.dev/docs/service-workers).
- Already-rendered stale-tab content is observational and does not prove server authorization. Reload and GET checks have separate findings. Immediate tab-wide logout synchronization is not an asserted feature.
- Screenshots, traces, automatic remediation, release automation, report comparison, and multiple workers are intentionally absent. No unsupported feature emits a manufactured PASS.
- A passing selected check is not a secure-app certification. JSON consumers must inspect selectedScenarios, each finding's phase/status/limitations, and coverage. Strict mode fails on INCONCLUSIVE, not on every NOT_TESTED observation.
